## 1. Context size – still 4096, still truncating

You set `OLLAMA_NUM_CTX=32768` on your **GCP VM** (systemd override), but this log is from your **Mac**, where Ollama is launched without that variable. On the Mac, you need to either:

- Set the environment variable before launching Ollama, **or**
- Create a custom model with `PARAMETER num_ctx 32768` via a Modelfile.

**Quick fix on your Mac:**

```bash

# then restart the Ollama app (or the `ollama serve` process)
```

Or, if you start Ollama manually:

```bash

```

After that, you’ll see `n_ctx = 32768` in the logs instead of `4096`, and the truncation warnings will disappear.

## 2. Prompt cache is useless with this model – plan accordingly

The log repeatedly shows:

```
forcing full prompt re-processing due to lack of cache data
(likely due to SWA or hybrid/recurrent memory)
erased invalidated context checkpoint ...
```

Gemma 4 12B uses **sliding window attention (SWA)** and hybrid layers that **invalidate the prompt cache** between requests. That means:

- Even if you send the exact same system prompt every time, the cache will be discarded.
- Each request will **always reprocess the full prompt** from scratch.

So the “static index” trick will not give you cached speed‑ups – but it’s still vital because it makes the prompt **dramatically smaller** (200–500 tokens instead of 5 000–7 000). The smaller prompt will still be processed at ~150–300 t/s, so the first‑request latency will be acceptable (maybe 2–5 seconds).  

The key is to **stop sending raw code** and start sending the compact JSON index.
